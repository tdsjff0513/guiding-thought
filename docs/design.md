# 指导思想 — DSH 宿主插件设计

日期：2026-11-19  
状态：设计已批准。  
范围：DeepSeek Harness 0.2.2-rc.3 桌面配置档的常驻 Host 插件。

## 意图

常驻指导思想，用来约束**所有问题**上的重大方向，不是针对某一个具体问题的工具箱。人完全不参与介入。思想不是技术路线：不把某一次碰巧有效的办法冻成永远正确的路线。

失败不是缺技能，是技能在、调查可以不在。压缩摘要把「根因是 X / 排除 Y / 世界是 Z」收成世界之后，后面的事实掀不回来。软件拦不住口头说「根因是 X」，但必须拦住把它锁成不可推翻的本本——至少在这一轮里把思想送进去，让动作对着当前问题从思想长出来。

## 为什么现在做

用户要把毛选里能操作的方法，固化成对事实上操作的约束：没有调查没有发言权；结论在调查末尾；现象只是入门向导；不正确的调查同样没有发言权；认识对不对看实践结果；捉住主要矛盾；不同质的矛盾用不同质的方法。

三句话钉死产品形态：

1. 这个插件不只针对某一个具体问题，是用来解决所有问题的。
2. 介入自然流畅，不需要人为任何参与。
3. 这只是指导思想，并不是技术路线。

## 要做成什么样

重大方向出现时，系统自己认出，把思想送进**这一轮**。日常读、搜、对细节不惊动。这一轮里具体查什么、动什么，对着**当前这个问题**从思想长出来。说出口的根因、排除、世界，只当待证伪；后面的事实可以掀。

指导思想就这几条：

- 没有调查，没有发言权
- 结论在调查末尾，不在先头
- 现象只是入门向导
- 不正确的调查同样没有发言权
- 认识对不对看实践结果
- 捉住主要矛盾
- 不同质的矛盾用不同质的方法

操作规则（从思想长出来的，不是冻死的办法）：

- 说出口的根因、排除、世界，只当待证伪
- 后面的事实可以掀前面的结论
- 日常读、搜、对细节不惊动
- 动作从当前问题的思想长，不从预装办法长

## 不要做成什么样

- 不是某一个具体问题的专用插件
- 不弹窗、不问你、不让你点「这是不是重大方向」
- 不预装 deny 列表，不预装任何一条具体办法
- 不把任何一条具体办法写成永远正确的路线
- 镇反、反右、捕杀比例等政治运动指令不入库
- 口头说「根因是 X」软件拦不住；失败态是把它锁成不可推翻的本本
- `systemPrompt.section()` 不是闸：技能在、调查可以不在，挂在系统提示里不够

## 路为什么是这一条

考虑过三条，都否了：

| 路 | 做什么 | 为什么否 |
|---|---|---|
| 硬闸 | `ctx.tools.guard()` / `tools/pre-execute` deny 一串工具 | 把思想降成开关；预装 deny 就是技术路线 |
| 询问闸 | `tools/pre-execute` `{ kind: 'ask' }` 或问用户「这是不是重大方向」 | 人零参与被打破；用户已说「你应该自己判断」 |
| 只挂提示 | `ctx.systemPrompt.section()` 常驻一段毛选 | 技能在、调查可以不在；进不了这一轮 |

剩下能对上三句话的：认、调、送进这一轮；动作从思想长。

## 已经钉死的「怎么做」（实现必须服从）

这些是形态约束，不是某一次具体办法。

1. **形态**：常驻 Host-only bundle。覆盖所有任务、所有会话。无 UI、无配置项、无人参与开关。
2. **重大方向**：正要把现象 / 本本 / 摘要收成根因 / 排除 / 世界，或没调查的路要当既定方向接着走。日常读、搜、对细节不是。
3. **送进这一轮**：思想必须进入当前这一轮模型可见的上下文。只挂系统提示、或 `agent.inject()` 却不唤醒、或错过已经 claim 的 pre-step，都不算送到。
4. **人零参与**：禁止 `ask`、禁止弹窗、禁止让用户点「这是不是重大方向」。
5. **不预装办法**：禁止 `ctx.tools.guard()`；禁止 `tools/pre-execute` 的 `deny` / `ask` / `cancel` 作为本插件的产品行为；禁止把任何一条具体办法写进插件当永远正确的路线。
6. **待证伪**：注入的文本必须写明根因 / 排除 / 世界可被后面的事实掀翻。压缩摘要不得被模型当成不可推翻的世界。
7. **政治运动指令不入库**：思想正文、locale、README、DETAIL 均不得出现镇反、反右、捕杀比例等作为可执行指令。
8. **目标运行时**：已安装 DSH `0.2.2-rc.3`（Desktop `PROFILE=desktop`）。插件用公开 Cordis 事件，不改 Harness 源码。
9. **安装面**：工作区写 bundle，用户审计划并明确同意之后才 `plugin_manager` `install_bundle`。不手改 `$DSH_HOME` / profile `package.json`。

## 留给以后做的人

怎么认出、怎么把文本拼进这一轮，是实现问题，不写进思想本身。实现必须满足上面九条。检测启发式可以换；换的时候不得把某一次具体办法冻成永远正确。

Builder 可自行决定、且不应回头问用户的：

- 侦测函数的具体词表 / 分类器（只要测例能证明：日常读搜不触发，收成根因/排除/世界会触发）
- 图标构图细节（须原创、36×36、无第三方商标）
- 是否对所有工具的 post-execute 扫文本，或先只盯会把结论冻进摘要的工具
- 测试是否用 `node:test` 还是等价的纯 ESM runner

Builder 不得自行改掉的：人零参与、不 deny、不 ask、思想正文那七条、待证伪、政治运动指令不入库、Host-only、无配置项。

## 约束（运行时事实，供计划引用）

来源：已安装 `@deepseek-ai/dsh-agent` / `@deepseek-ai/dsh-tools` / `@deepseek-ai/dsh-system-prompt` / `@deepseek-ai/dsh-llm` 0.2.2-rc.3。

- Host 插件：`export function apply(ctx, config)`；可选 `export const inject`、`export const Config`。
- Bundle：`package.json` 的 `dsh.bundle.patch` 指向 YAML；`plugin_manager` `install_bundle` 安装。
- `agent/pre-step`：waterfall。可拒绝或替换进入该步的 `messages`。改写时必须 `{ ...decision, messages }`，保留 `startsRequestSeries`。
- `agent.inject()`：排队到下一次 admitted pre-step，**不唤醒**；可能错过已经 claim 的 batch。
- `agent.followup()`：会唤醒。本插件不得用 followup 打扰用户可见的下一轮对话（那会变成另一次人话）。
- `ctx.tools.guard()`：同步、只能 deny。本插件禁用。
- `tools/pre-execute`：`allow` / `deny` / `cancel` / `ask`。本插件对这四者只走 `next()`（允许）。
- `tools/post-execute`：`accept` 可带 `additionalContexts?: UserMessage[]`，进入**同一 turn 的下一次请求**。
- `ctx.systemPrompt.section()`：加提示文本。不是闸。
- `UserMessage`：`{ id, role: 'user', content, source }`。`MessageSource.kind` 可扩展；注入用插件自有 `kind`，不要冒充 `user`。
- `ContextForm` `notice` 的 `summary` 上限 120 字（`CONTEXT_SUMMARY_MAX_CHARS`）。
- 按 agent 注册：在 `agent/created` 里用 `agent.ctx.effect()`，并把 disposer 留在插件自己的 effect 里。
- 缺 tools 服务时插件应不激活：`inject: ['tools']`。

## 成功长什么样

装上并开新会话之后：

- 用户问「读这段日志」——这一轮看不到指导思想（不惊动）。
- 用户问「根因是什么 / 把这条路排除」——这一轮模型可见指导思想，且不必用户点任何东西。
- 某次工具结果把「根因是 X / 排除 Y / 世界是 Z」收成摘要——同一 turn 下一次模型请求能看见「待证伪，后面的事实可以掀」。
- 插件从不弹出「这是不是重大方向」。
- 插件从不因为本插件而 deny 任何一个工具。
- 思想正文里没有镇反、反右、捕杀比例。
